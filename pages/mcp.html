MCP
AI連携の、共通コネクタ。

Model Context Protocol。AIと社内システム・SaaSをつなぐためのオープン標準。2024年末の登場からわずか1年半で主要ベンダーが軒並み採用し、「AI界のUSB-C」と呼ばれる事実上の標準になった。現在は中立の標準化団体が管理している。

In one sentence

機器ごとにバラバラだったケーブルが、
USB-Cの一本に揃った。

Diagram 01

Before / After — 配線問題の解消

AI連携の最大のボトルネックは、モデルの性能ではなく「つなぎ込み」の工数だった。

Before ／ 個別配線
AI × システムの数だけ、専用開発

AIが3種類、社内システムが10個なら、最大30本の専用連携を開発・保守する必要があった（N×M問題）。AIを乗り換えると連携は作り直し。

  • 連携ごとに個別のAPI開発
  • ベンダーを替えると資産が消える
  • 保守コストが増え続ける
After ／ MCP
システム側に「口」を1つ作れば、どのAIからも挿せる

システム側が「MCPサーバー」という規格化された接続口を1つ用意すれば、MCP対応のAIすべてがそのまま接続できる（N+M）。

  • 接続口は1システムにつき1つ
  • AIを乗り換えても連携資産は残る
  • 主要SaaSは公式MCPサーバーを提供済み
「つなぎ込み」の時代から、
「差すだけ」の時代へ。
Why it matters

自社にとっての意味 — 3つ

規格の話に見えて、実は投資判断と統制の話。

01

連携の内製がぐっと軽くなる

基幹システムや社内DBに一度MCPサーバーを立てれば、チャットAIからもエージェントからも同じ口で接続できる。第9回のエージェント・パイプラインの土台になる。

02

ベンダーロックインの回避

モデルの主役は数ヶ月ごとに入れ替わる時代。連携をMCPで組んでおけば、AI本体を乗り換えても接続資産はそのまま使える。

03

権限と監査の一元管理

「誰のAIが、どのシステムに、何をして良いか」を会社のID基盤で集中管理する企業向け認証の仕組みが整備された。野良連携（シャドーAI）対策としても重要。

Plain Language

用語解説 — むずかしい言葉をやさしく

このページに出てくる専門用語を、業務や日常に置き換えて理解する。

MCPサーバー MCP Server

システム側に用意する「AI用の接続口」。そのシステムでできる操作（検索・登録・更新など）をAIに開示する。ビルの受付窓口。用件ごとの手続きが整理されている。

MCPクライアント MCP Client

AI側の差し込みプラグ。チャットAIやエージェントがこれを使ってサーバーに接続する。USB-Cケーブルの、AI側の端子。

ツール Tool

MCPサーバーがAIに開示する個々の操作。「在庫を検索する」「伝票を起票する」など。受付窓口に並んだ申請書の種類。

A2A Agent to Agent

MCPが「AIと道具」をつなぐ規格なのに対し、「AI同士」の連携を担う標準プロトコル。第8回のマルチエージェントで登場。MCPが内線電話なら、A2Aは部署間の連絡便。
