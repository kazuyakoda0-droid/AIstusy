SESSION 07 · 実践・道具立て

/名前 で呼び出せる、自分専用の依頼文

Slash commands — your prompts, saved.

/goal や /loop の頭に付いている「/」は何なのか。ここを押さえると、この回の4つの部品が一本につながります。

結論から言うと、よく使う依頼文を登録して、短い名前で呼べるようにしたものです。それだけです。

ひとことで言うと

スラッシュコマンドは「登録済みの依頼文」。/goal や /loop も、あらかじめ用意されたコマンドのひとつにすぎません。自分で作ることもできます。

Basics

打った瞬間に、裏で何が起きているか

「/週報」と打つと、裏では登録しておいた長い依頼文が、そのまま展開されて実行されます。魔法の機能ではなく、単語登録や定型文と同じ発想です。

＄ /週報 今週 -- 裏で実行されている内容 -- あなたは業務報告をまとめる担当者です。 今週の作業ログを読み、次の形式で週報を作ってください。 1. 今週やったこと（3〜5行） 2. 数字（件数・時間） 3. 来週やること 4. 相談したいこと 社内向けなので敬語、300字程度でお願いします。
たとえるなら

電話の短縮ダイヤル。番号を覚えているわけではなく、登録してある長い番号を短い操作で呼び出しているだけ。中身は自分で登録した内容そのままです。

Make

作り方は、.md を1枚置くだけ

1
依頼文を .md ファイルに書く
毎回打っている内容を、そのまま貼るだけでかまいません。第7回の .md の話がここで効いてきます。
2
決められた場所に置く
ツールごとに「コマンド置き場」のフォルダがあります。そこに置いたファイル名が、そのままコマンド名になります。
3
引数を受け取れるようにする（任意）
「/週報 今週」の"今週"のような部分を、依頼文の中で受け取れます。使う側は短く打てて、中身は詳しく書けます。
4
チームで共有する
ファイルを共有すれば、全員が同じコマンドを使えます。頼み方が揃うので、出てくるものも揃います。
効果が大きいのは、実は共有のほう

個人の時短より、「うちのチームの週報の頼み方はこれ」と決まることの効果が大きいです。人によって出来上がりがバラバラになる問題が、コマンドを配るだけで消えます。

vs Skill

Skill との違いは、呼ぶのが誰か

スラッシュコマンド
人が「/週報」と明示的に呼ぶ
使うタイミングを人が決めます。定型作業を自分の意思で始めるときの道具。
Skill（手順書）
AIが「この作業なら、あの手順書が要る」と自分で開く
呼ぶ判断もAIに任せます。どんな依頼が来ても、うちのやり方で処理させたいときの道具。

どちらが優れているという話ではありません。「自分で始める作業」はコマンド、「どう頼まれても守ってほしいやり方」は Skill。この使い分けで十分です。

迷ったときの決め方

毎回自分で打っているものはコマンドにする。「これ言い忘れると困るな」と思うものは Skill か .md に書く。言い忘れが怖いものは、人に思い出させない側に置くのが原則です。

Tips

作るときのコツ

TIP 1
名前は短く、動詞で
「/週報」「/議事録」「/見積チェック」。打つ気にならない長さの名前は、結局使われません。
TIP 2
1コマンド1仕事
欲張って全部入れると、微妙に用途が違うときに使えなくなります。分けたほうが結局出番が多いです。
TIP 3
完成させてから配る
自分で2〜3週間使って、直し終わったものをチームに配ります。作りかけを配ると、直すコストが人数分かかります。
