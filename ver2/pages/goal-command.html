SESSION 07 · 実践・道具立て

/goal は、「終わりの定義」を先に渡すコマンド

Declare the finish line first.

AIエージェントに長い作業を頼むと、よくこうなります。途中まで やって「できました」と言ってくる。

それを防ぐのが /goal です。ゴール条件を先に宣言しておくと、満たすまで止まらなくなります。

ひとことで言うと

/goal は「これが達成できたら終わり」を先に宣言するコマンド。AIは条件を満たすまで、途中で終わらずに作業を続けます。

Problem

なぜ必要になるのか

エージェントは「考える → 動く → 結果を見る」をくり返しますが、どこで止まるかは、AI自身の判断です。そして、その判断はときどき甘い。

10個お願いしたのに7個で「完了しました」。テストを通していないのに「できました」。——これが起きるのは、「終わり」の定義があいまいだからです。

たとえるなら

仕事を頼むときの「完了条件」と同じです。「資料まとめといて」だけだと人によって出来上がりがバラバラですが、「A社とB社の比較表を作って、数字は出典つきで」と言えば揃います。

How

使い方は、拍子抜けするほど簡単です

＄ /goal 今月の請求書PDFを全部読んで一覧表にする。 金額が発注データと合わない行は赤くする。 43件すべて処理し終わるまで終わらないこと。 → ゴールを受け取りました。条件を満たすまで作業を続けます。 … 20件処理 … 35件処理 … 43件処理完了 → 3件で差額を検出。一覧表を作成しました。 → ゴール条件を満たしたので、終了します。

仕組みとしては、「作業を終わろうとしたとき、条件を満たしているか毎回チェックする」という見張りが付くイメージです。満たしていなければ、AIは作業に戻されます。

途中でやめたくなったら

ゴールは途中で取り消せます（ツールによって /goal clear など）。条件を満たしたときは自動で外れるので、通常は何もしなくて大丈夫です。

Writing

良いゴールの書き方 / 悪いゴールの書き方

BAD — 判定できない
請求書をいい感じにチェックして
「いい感じ」を誰が判定するのでしょうか。AIは「まあこれでいいか」で止まります。
GOOD — 判定できる
43件すべての請求書を処理し、差額のある行を一覧表に赤字で出す。処理件数を最後に報告すること
数と形が決まっているので、達成したかどうかが機械的に判定できます。
TIP 1
数を入れる
「43件すべて」「3案」「全ファイル」。数があると、途中で止まったことが一目で分かります。
TIP 2
成果物の形を書く
「一覧表にして」「Markdownで」「表形式で」。形が決まると、判定が明確になります。
TIP 3
確認方法まで書く
「最後に処理件数を報告すること」。自己申告させると、AI自身が抜けに気づきます。

Caution

気をつけること

止まらなくなる、ということは間違った方向にも走り続けるということです。長時間の作業を任せる前に、必ず小さい範囲で試してください。

また、「送る」「消す」「支払う」といった取り返しのつかない操作は、ゴールに含めないでください。そこは人の承認を挟む場所です（Human in the Loop）。
