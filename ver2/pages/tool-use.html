SESSION 06 · 自律型AI

AIが自分で道具を取りに行くようになった

Tool use, function calling, MCP.

AIモデルは、そのままでは文章を返すことしかできません。検索も、ファイルを開くことも、システムへの書き込みもできない。

その壁を越えるのがツールを使う（Tool Use）という仕組みです。

ひとことで言うと

AIが「これは自分では分からないから、検索を使おう」と自分で判断して道具を呼ぶ。これができると、一気に実務で使えるようになります。

Basics

ツールとは、要するに何か

AIに使わせる「機能」のことです。Web検索、電卓、社内データベースの照会、ファイルの読み書き、メール送信——どれもツールです。

重要なのは、人がツールを選ぶのではなく、AIが自分で選ぶ点です。「今日の為替は？」と聞かれたAIは、記憶で答えるのではなく「これは最新情報が要るな」と判断して検索ツールを呼びます。

たとえるなら

工具箱を渡された職人。何を使うかは本人が決めます。渡していない工具は、当然使えません。

MCP

MCP — 道具の「差し込み口」を共通にする

ツールを1つ増やすたびに専用のつなぎ込みを作っていては、いつまでも増えません。そこでつなぎ方を共通の規格にそろえようという動きが出てきました。それが MCP（Model Context Protocol）です。

難しく考えなくて大丈夫です。USBのようなものだと思ってください。規格が同じなら、どのAIにも、どの道具にも挿さる。

実務でどう効くか

「うちの基幹システムをAIから見られるようにしたい」というとき、MCP対応の入り口をひとつ作れば、複数のAIツールから使い回せます。個別に作り込むより、結果的に安く早く済みます。

Caution

道具を渡す＝権限を渡す、ということ

ツールを与えるということは、AIにその操作の権限を渡すということです。読むだけの道具と、書き換えられる道具では、リスクがまったく違います。

SAFE
読むだけの道具
検索、ファイルを読む、データベースを見る。間違えても元に戻せます。まずここから渡すのが定石。
CAREFUL
書き換える道具
ファイルの保存、システムへの登録。取り返しがつく範囲かどうかを、事前に確認しておきます。
GATE
外に出る道具
メール送信、投稿、支払い。ここは必ず人の承認を挟む。自動で実行させてはいけません。
