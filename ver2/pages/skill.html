SESSION 07 · 実践・道具立て

Skill は、必要なときだけ開くマニュアル棚

Skills — reusable know-how, loaded on demand.

毎回おなじ説明をするのが面倒——という悩みを、まるごと解決する仕組みです。

よくやる作業の進め方を書いた手順書を用意しておき、AIに必要なときだけ読ませます。

ひとことで言うと

Skill は「この作業は、うちではこうやる」を書いた手順書のセット。棚に置いておくと、AIが必要になったときだけ取り出して読みます。

Problem

なぜ必要になるのか

「請求書のチェックをして」とAIに頼むとします。一般論としては正しいチェックをしてくれますが、うちの会社のやり方は知りません。

かといって、毎回チャットに手順を全部貼りつけるのは面倒ですし、抜けも出ます。かといって、全部を常に読ませておくと、量が多すぎてAIが処理しきれません。

たとえるなら

職場の棚に並んだマニュアル。全部を暗記している人はいません。必要になったときに背表紙を見て、該当する1冊だけ取り出す。Skill はまさにこれです。

How

仕組みは、2段構えになっています

1
ふだんは「名前と説明」だけ見えている
「請求書チェックの手順 — 請求書の突合と差額検出をするときに使う」。背表紙だけが見えている状態です。
2
関係しそうな作業が来たら、中身を読み込む
AIが「今回はこれが要る」と判断したときだけ、手順書の全文を開きます。
3
書かれた通りに作業する
「うちのやり方」で作業が進みます。毎回説明する必要はもうありません。
なぜ2段構えなのか

AIが一度に読める文章量には上限があるからです。手順書を100個持っていても、常に全部読ませていたらパンクします。背表紙だけ見せて、必要な1冊だけ開く——この設計のおかげで、いくらでも増やせます。

Inside

中身は、ただの .md ファイルです

--- name: invoice-check description: 請求書の突合と差額検出をするときに使う --- # 請求書チェックの手順 ## 1. 読み取る - 取引先名 / 発行日 / 品目 / 数量 / 単価 / 税込金額 を抽出する - 「御中」「様」は取引先名から除く ## 2. 突合する - 発注データと、品目・数量・単価を照合する - 差額が1円でもあれば、必ず報告する（丸めない） ## 3. 報告する - 一覧表にして、差額のある行を赤くする - 判断はしない。人の確認に回す

見ての通り、プログラムではありません。日本語の手順書です。だから、業務を知っている人が自分で書けます。むしろ、その人が書くのがいちばん正確です。

Value

これがすごいのは、資産になるところ

チャットに毎回貼りつけた指示は、その会話が終われば消えます。でも Skill として書いたものは残り、共有でき、改善できます。

「◯◯さんに聞かないと分からない」がひとつ減り、しかもそれが人ではなくファイルとして組織に残る。第4回のRAGとは違う角度から、属人化を解く仕組みです。

MERIT 1
毎回説明しなくてよくなる
一度書けば終わり。しかも書き漏らしがなくなります。
MERIT 2
やり方が揃う
誰がAIに頼んでも、同じ手順で処理されます。品質のばらつきが消えます。
MERIT 3
改善が積み上がる
「ここも見てほしい」と気づいたら、手順書に1行足すだけ。次から全員に効きます。
第8回への伏線

役割の違うAIを何匹も動かす「マルチエージェント」では、それぞれに違う Skill を持たせます。Skill = その担当者の職務経験、というイメージです。
