SESSION 07 · 実践・道具立て

AIが自分で書いて、動かして、直すようになった

It writes, runs, and fixes its own code.

「コーディング」と聞くと自分には関係ないと思うかもしれませんが、逆です。

今まで「システム部門にお願いするしかなかった人」にこそ、いちばん効く話です。

ひとことで言うと

AIが自分でプログラムを書き、実行し、エラーを読んで直すようになりました。つまりコードが書けない人でも、言葉だけで自分用の道具を作れるということです。

Change

何が変わったのか

これまで
AIにコードを書いてもらう → 人がコピーして貼る → 動かす → エラーが出る → エラー文をコピーしてAIに聞く → …
結局、人が運搬役をやっていました。動かない理由が分からないと、そこで詰みます。
いま
AIが自分で書く → 自分で動かす → エラーを自分で読む → 自分で直す → 完成するまで繰り返す
人がやるのは、最初のお願いと、最後の確認だけになりました。

この「自分で動かして、自分で直す」を自律デバッグと呼びます。地味に見えますが、非エンジニアにとっては決定的な変化です。エラーで詰まらなくなったからです。

Example

具体例 / 写真100枚に日付を入れる

依頼 > このフォルダの現場写真100枚すべての右下に 「2026年 工事完了」と白文字で入れて、別フォルダに保存して -- AIの作業 -- 1. 処理する手順（プログラム）を書いた 2. 試しに1枚で動かしてみた 3. エラー：日本語フォントが見つかりません 4. 「システムのフォントに切り替えます」→ 自分で修正 5. もう一度1枚でテスト → OK 6. 100枚に対して実行 → 完了しました

3〜4行目がポイントです。エラーが出た瞬間、人に聞きに来ませんでした。自分で読んで、自分で直しています。

手作業なら丸一日、外注すれば数万円かかっていた作業が、数分で終わります。

For you

非エンジニアの、現実的な使いどころ

CASE 1
ファイルの一括処理
リネーム、形式変換、フォルダ分け、透かし入れ。「100個あるから諦めていた」作業が全部対象です。
CASE 2
Excel / CSV の整形
複数ファイルの結合、表記ゆれの統一、突合チェック。手作業でやると丸一日かかるやつ。
CASE 3
小さな社内ツール
入力フォーム、集計画面、チェックリスト。1人〜1課で使うものなら、その日の午後にできます。
CASE 4
定型レポートの自動作成
毎週同じ形でまとめている資料。一度作れば、あとは /loop で回せます。
「開発の民主化」とは

道具を作れる人が、エンジニアだけではなくなること。いちばん困っている人が、自分で道具を作れるのが、実は最短ルートです。仕様を説明する手間がゼロなので。

Caution

気をつけること

自分で動かせるということは、間違ったものも自分で動かせてしまうということです。とくにファイルの削除・上書きは注意してください。

最初のうちは、コピーしたフォルダで試すのが鉄則です。元データに直接やらせないこと。これだけ守れば、大きな事故は起きません。
